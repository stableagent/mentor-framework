# Contributing to Mentor Framework

Contributions should improve the organizational mentoring framework without coupling its semantics to a particular AI provider or application.

Before changing taxonomy, check stable IDs, role/domain relationships, authority rules, routing effects, localization implications, examples and schemas.

Changes to standards, schemas, IDs, authority or routing behavior require an explanation of compatibility impact.

Canonical JSON is authoritative. Derived TOON representations must be generated or updated from canonical data rather than edited as an independent source.

Fixed system identities require explicit architectural review. Do not rename or repurpose nahid, armin, mojgan or saeed casually.

Do not introduce global mentor rankings. Prefer capability-based selection and deterministic routing rules.

Changes affecting regulated or high-risk domains must preserve external-review requirements.

Useful contributions include the change itself, updated schemas when contracts change, updated examples when behavior changes, conformance implications and provenance/version information when applicable.
